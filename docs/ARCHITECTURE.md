# Architecture

How satellion.com is built, for contributors. The decisions behind it are in
[docs/adr/](adr/README.md).

## What the site serves

| Path | Source | Layout |
|---|---|---|
| `/` | `content/index.md` | `company` (Satellion's home) |
| `/passmcp/` | `content/passmcp/index.md` | `index` (passmcp's product page) |
| `/passmcp/docs/` | passmcp's `docs/` at a release, built with MkDocs | passmcp's own |
| `/passmcp/sample/` | passmcp's sample report at a release | passmcp's own |
| `/<module>/` for each Go module | `content/<module>/index.md` | `doc`, with `go_import` and `go_source` meta tags |
| `/attestation/mcp-evaluation/v1/`, `/attestation/a2a-evaluation/v1/`, `/graph/v1/` | `content/attestation/`, `content/graph/` | `doc` |
| `/.well-known/security.txt` | the `security_*` keys in `content/index.md` | generated by SSG |
| `/coverage.json` | `make coverage` over `scripts/` | shields.io endpoint document |

## Repository layout

```text
content/      Markdown pages; front matter carries each page's copy and numbers
_layouts/     SSG templates, CSS and JS (vendored from the SSG theme suite, MIT)
brand/        Satellion's and passmcp's icons and logos
images/       Photographs and the rendered social cards
cards/        HTML sources for the social cards, rendered by scripts/cards.py
scripts/      The build's Python and shell helpers, and their unittest tests
docs/         This document, the ADRs and the release notes
ssg.toml      SSG's configuration: site name, base URL, directories
Makefile      Every build and gate target
```

## The build

`make core` (ADR 0002) needs Python and SSG 0.0.68:

1. The Makefile refuses any SSG other than 0.0.68.
2. `ssg build -f ssg.toml` renders `content/` through `_layouts/` into `dist/`.
   SSG wipes `dist/` first, so static files are copied after it.
3. `images/` and both icon sets are copied in.
4. `scripts/security_txt.py` validates security.txt and fails when its
   Expires date is under 30 days away; the file is also copied to
   `/.well-known/`.
5. `scripts/modules.py` fails when a Go module page is missing or carries
   the wrong `go-import` tag (ADR 0004).
6. `scripts/quality_gate.py` fails the build unless SSG's
   `quality-gate-report.json` passes every pillar and its
   `accessibility-report.json` lists no issue, and `scripts/strict_csp.py`
   fails it unless every page carries the policy in `_layouts/csp.html`
   (the same as Cloudflare's header) and needs no inline script or style
   and nothing from another origin.
7. `CNAME` is written for GitHub Pages.

`make site` (ADR 0001) adds, before `core`: a passmcp checkout at a release
tag, its sample report, `scripts/site_data.py` writing the product page's
numbers from that report, and the manual. After `core` it copies the manual
and sample into `dist/passmcp/` and runs passmcp's sitemap generator over the
finished tree.

## Keeping pages true

- `scripts/site_data.py` writes every check count and the sample report's
  figures; `make check-data` fails a pull request whose committed page
  differs from what the release produces.
- `scripts/modules.py` and its tests hold the Go module pages to the list
  of modules.
- `scripts/family.py` renders the family table (`_layouts/family.html`)
  from passmcp's `ecosystem.json`, reading manifest schemas 1 and 2;
  `make family` writes it and `make check-family` fails when it differs.
- `scripts/verify-release-versions.sh` fails when a version reference
  differs from the newest CHANGELOG release.
- `scripts/readme-check.sh` holds README.md to the portfolio template, and
  `scripts/name-guard.sh` keeps the retired product name out of the tree.

## Deployment

`.github/workflows/pages.yml` builds on every push to `main`, daily and on
demand, and deploys `dist/` to GitHub Pages with the custom domain
satellion.com. It builds `make site` when passmcp has a release and
`make core` otherwise, then adds `coverage.json`.
